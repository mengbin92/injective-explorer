- ✅ 缓存未命中时,并发请求共享同一个查询结果
- **效果: 峰值时减少50-80%数据库查询**

#### ⚠️ 响应时间预估

| 场景 | 目标 | 缓存命中 | 缓存未命中 | 评估 |
|-----|------|---------|-----------|------|
| 页面首屏 | ≤ 2s | <100ms | 2-5s | ⚠️ 未命中可能超时 |
| 列表分页 | ≤ 1s | <200ms | 1-3s | ⚠️ 未命中可能超时 |
| 搜索结果 | ≤ 500ms | <200ms | 500ms-3s | ⚠️ 未命中可能超时 |
| **API接口** | ≤ 500ms | <100ms | **500ms-3s** | ❌ **需要添加缓存** |

#### ⚠️ 结论

**问题根因:**
1. API查询没有Redis结果缓存(只有RequestCoalescer防并发重复)
2. 统计数据TTL过长(5分钟 vs 需求10秒)
3. HTTP超时设置过长(30秒,建议15秒)

**当前响应时间组成(缓存未命中):**
```
API响应时间 = 网络延迟(10ms) + 限流检查(5ms) + 数据库查询(100-500ms) + 业务逻辑(50-200ms) + JSON序列化(10ms)
           ≈ 175-725ms
```

**优化后预期:**
```
API响应时间(缓存命中) = 网络延迟(10ms) + 限流检查(5ms) + Redis查询(1ms) + JSON序列化(10ms)
                       ≈ 26ms (远低于500ms目标)
```

#### 整改项3: 添加API查询缓存 ⭐⭐⭐⭐⭐

**问题:** API查询没有Redis结果缓存,导致响应时间>500ms

**整改措施:**

**步骤1: 定义缓存helper函数**

```go
// 新文件: internal/service/cache_helper.go
package service

import (
    "context"
    "encoding/json"
    "time"

    "injective-explorer/provider/cache"
    "github.com/redis/go-redis/v9"
)

// GetCached 获取缓存数据
func GetCached(ctx context.Context, key string, dest interface{}, ttl time.Duration) (bool, error) {
    redisClient := cache.GetRedisClient()
    if redisClient == nil {
        return false, nil  // Redis不可用时,跳过缓存
    }

    data, err := redisClient.Get(ctx, key).Bytes()
    if err == redis.Nil {
        return false, nil  // 缓存未命中
    }
    if err != nil {
        return false, err
    }

    if err := json.Unmarshal(data, dest); err != nil {
        return false, err
    }

    return true, nil  // 缓存命中
}

// SetCached 设置缓存数据
func SetCached(ctx context.Context, key string, value interface{}, ttl time.Duration) error {
```

#### 整改项9: 实现本地内存缓存 ⭐⭐

**问题:** 所有缓存都走Redis,增加网络延迟

**整改措施:**

```go
// 新文件: provider/cache/tiered_cache.go
package cache

import (
    "time"

    "github.com/dgraph-io/ristretto"
    "github.com/redis/go-redis/v9"
)

// TieredCache 二级缓存(本地+Redis)
type TieredCache struct {
    local *ristretto.Cache
    redis *redis.Client
}

func NewTieredCache(redisClient *redis.Client) (*TieredCache, error) {
    local, err := ristretto.NewCache(&ristretto.Config{
        NumCounters: 1e7,     // 1000万个计数器
        MaxCost:     1 << 30, // 1GB
        BufferItems: 64,
    })
    if err != nil {
        return nil, err
    }

    return &TieredCache{
        local: local,
        redis: redisClient,
    }, nil
}

func (tc *TieredCache) Get(ctx context.Context, key string, dest interface{}) (bool, error) {
    // 1. 查询本地缓存
    val, found := tc.local.Get(key)
    if found {
        // 本地缓存命中
        return true, nil
    }

    // 2. 查询Redis
    data, err := tc.redis.Get(ctx, key).Bytes()
    if err == redis.Nil {
        return false, nil  // 未命中
    }
    if err != nil {
        return false, err
    }

    // 3. 写入本地缓存
    tc.local.Set(key, data, 1)
    tc.local.Wait()

    return true, nil
}

func (tc *TieredCache) Set(ctx context.Context, key string, value interface{}, cost int64, ttl time.Duration) error {
    // 同时写入本地和Redis
    tc.local.SetWithTTL(key, value, cost, ttl)
    return tc.redis.Set(ctx, key, value, ttl).Err()
}
```

**预期效果:**
- ✅ 减少Redis网络延迟(0.5-1ms → 0.01ms)
- ✅ 减轻Redis压力
- ✅ 提升缓存命中响应速度

## 五、风险评估与缓解

### 5.1 高风险项

| 风险 | 影响 | 概率 | 缓解措施 |
|-----|------|------|---------|
| **缓存容量扩大导致Redis OOM** | 服务不可用 | 中 | 1. 监控Redis内存<br>2. 设置maxmemory和淘汰策略<br>3. 逐步调整TTL |
| **IP限流提高被DDoS利用** | 服务不可用 | 中 | 1. Nginx/Envoy层限流<br>2. API保持Token严格限流<br>3. 监控异常流量 |
| **工作线程池扩大导致资源耗尽** | 性能下降 | 中 | 1. 逐步调整<br>2. 监控CPU/内存<br>3. 使用pprof分析 |
| **TTL缩短增加数据库压力** | 查询变慢 | 高 | 1. 优化查询和索引<br>2. 压测验证<br>3. 监控慢查询 |

```bash
#!/bin/bash
# 压测脚本: run_load_test.sh

BASE_URL="http://localhost:8000"
OUTPUT_DIR="./load_test_results"
mkdir -p "$OUTPUT_DIR"

echo "=== Starting Load Tests ==="

# 测试1: 页面并发 50 req/s
echo "Test 1: Page concurrency 50 req/s"
hey -n 3000 -c 50 -m GET "$BASE_URL/" \
  -o "$OUTPUT_DIR/test1_page_concurrency.json"

# 测试2: API并发 100 QPS
echo "Test 2: API concurrency 100 QPS"
hey -n 6000 -c 100 -m GET "$BASE_URL/api/v1/block/latest" \
  -o "$OUTPUT_DIR/test2_api_concurrency.json"

# 测试3: 200并发持续5分钟
echo "Test 3: 200 concurrent users for 5 minutes"
hey -z 5m -c 200 "$BASE_URL/" \
  -o "$OUTPUT_DIR/test3_200_concurrent_5min.json"

# 测试4: 100 QPS持续10分钟
echo "Test 4: 100 QPS for 10 minutes"
hey -z 10m -q 100 -m GET "$BASE_URL/api/v1/transactions" \
  -o "$OUTPUT_DIR/test4_100_qps_10min.json"

echo "=== Load Tests Completed ==="
echo "Results saved to: $OUTPUT_DIR"
```
