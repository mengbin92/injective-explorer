# HTTP接口压力测试工具

这是一个用于对injective-explorer HTTP接口进行并发压力测试的工具。

## 功能特性

- ✅ 支持多接口并发测试
- ✅ 可配置并发数、持续时间、请求总数
- ✅ 实时统计QPS、延迟、成功率等指标
- ✅ 支持状态码分布统计
- ✅ 支持指定单个接口或测试所有接口
- ✅ 详细的测试报告输出

## 编译

```bash
cd cmd/loadtest
go build -o loadtest main.go
```

或者从项目根目录：

```bash
go build -o bin/loadtest ./cmd/loadtest
```

## 使用方法

### 基本用法

```bash
# 使用默认配置测试30秒（10并发）
./loadtest -d 30s

# 测试1000个请求（10并发）
./loadtest -n 1000

# 指定服务器地址和并发数
./loadtest -url http://localhost:8000 -c 50 -d 1m

# 测试单个接口
./loadtest -endpoint /demo/health -c 20 -d 30s

# 详细输出模式
./loadtest -v -c 10 -d 30s
```

### 参数说明

| 参数        | 说明               | 默认值                  | 示例                             |
| ----------- | ------------------ | ----------------------- | -------------------------------- |
| `-url`      | 服务器基础URL      | `http://localhost:8000` | `-url http://192.168.1.100:8000` |
| `-c`        | 并发数             | `10`                    | `-c 50`                          |
| `-d`        | 测试持续时间       | `0`                     | `-d 30s`, `-d 5m`                |
| `-n`        | 总请求数           | `0`                     | `-n 1000`                        |
| `-timeout`  | 请求超时时间       | `30s`                   | `-timeout 10s`                   |
| `-endpoint` | 指定测试的接口路径 | `""` (测试所有接口)     | `-endpoint /demo/health`         |
| `-v`        | 详细输出模式       | `false`                 | `-v`                             |

**注意**: `-d` 和 `-n` 必须至少指定一个。

### 测试的接口列表

工具会自动测试以下接口：

1. **健康检查** - `/demo/health`
2. **最新区块高度** - `/demo/block/latest-height`
3. **最新区块列表** - `/demo/block/latest`
4. **按高度获取区块** - `/demo/block/by-height`
5. **最新交易列表** - `/demo/transaction/latest`
6. **交易统计** - `/demo/transaction/stats`
7. **24小时失败交易** - `/demo/transaction/failed-24h`
8. **账户信息** - `/demo/account/info`
9. **账户余额** - `/demo/account/balances`
10. **账户交易** - `/demo/account/transactions`

## 使用场景

### 1. 快速性能测试

```bash
# 30秒快速测试，中等并发
./loadtest -c 20 -d 30s
```

### 2. 高并发压力测试

```bash
# 100并发，持续1分钟
./loadtest -c 100 -d 1m
```

### 3. 特定接口测试

```bash
# 只测试健康检查接口
./loadtest -endpoint /demo/health -c 50 -d 30s
```

### 4. 固定请求数测试

```bash
# 发送10000个请求，50并发
./loadtest -n 10000 -c 50
```

### 5. 生产环境测试

```bash
# 测试生产环境（注意：谨慎使用，避免影响生产）
./loadtest -url https://api.example.com -c 10 -d 30s -timeout 10s
```

## 性能优化建议

1. **逐步增加并发数**: 从低并发开始，逐步增加，观察系统表现
2. **监控服务器资源**: 测试时监控CPU、内存、网络等资源使用情况
3. **关注错误率**: 如果错误率超过5%，可能需要降低并发数或检查服务器
4. **测试不同接口**: 不同接口的性能可能差异很大，建议分别测试
5. **长时间测试**: 使用 `-d` 参数进行长时间测试，观察系统稳定性

## 注意事项

⚠️ **警告**: 
- 压力测试会对服务器造成负载，请确保在测试环境进行
- 不要在生产环境进行高强度压力测试
- 建议在测试前通知相关人员
- 注意观察服务器资源使用情况，避免过载

## 故障排查

### 连接被拒绝

```
错误: 连接被拒绝
```

**解决方案**: 检查服务器是否运行，URL是否正确

### 超时错误过多

**解决方案**: 
- 增加 `-timeout` 参数值
- 降低并发数 `-c`
- 检查服务器性能

### 所有请求都失败

**解决方案**:
- 检查服务器日志
- 确认服务器地址和端口正确
- 检查网络连接

## 扩展开发

如果需要添加新的测试接口，可以修改 `main.go` 中的 `endpoints` 数组：

```go
var endpoints = []EndpointConfig{
    {
        Name:   "新接口名称",
        Path:   "/demo/new-endpoint",
        Method: "GET",
        Params: map[string]string{
            "param1": "value1",
        },
    },
}
```
